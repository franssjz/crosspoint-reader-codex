# Auto-Flash And GitHub Pages

Read this before changing `docs/flash.html`, browser flasher code, Pages
publishing, firmware manifests, or release sync.

## Invariant

The auto-flash page must flash the latest firmware published as a GitHub release
asset. It must not silently flash a random local `firmware.bin`.

The browser copies exist so GitHub Pages can serve them reliably, but their
source of truth is the latest release's assets. Never hand-craft
`docs/firmware/firmware-x4pro.bin`; it appears only when the sync script finds
`<tag>-x4pro.bin` on the published release.

## Two Binaries, Three Devices

| Device option | Chip | Image | Local copy | OTA slot |
|---|---|---|---|---|
| `x4` (Xteink X4) | ESP32-C3 | `<tag>.bin` | `docs/firmware/firmware.bin` | 0x640000 |
| `x3` (Xteink X3) | ESP32-C3 | `<tag>.bin` (same image) | `docs/firmware/firmware.bin` | 0x770000 |
| `x4pro` (Xteink X4 Pro) | ESP32-S3 | `<tag>-x4pro.bin` | `docs/firmware/firmware-x4pro.bin` | 0x7E0000 |

The X4 and X3 share one C3 image and differ only in partition layout. The X4
Pro is a different chip with its own binary; its device option is always shown,
but flashing stays disabled with an explanatory note until the manifest carries
a `devices.x4pro` entry.

## Key Files

- `docs/flash.html`: user-facing browser flasher page. `DEVICE_CONFIGS` holds
  per-device `chip`, `firmwareKey`, `appSize`, `appOffsets`, `partitions`; the
  `FALLBACK_RELEASE` block is regenerated by the sync script.
- `docs/assets/site.js`: shared site text and flasher UI strings (`en` and
  `es` are complete; other languages fall back to `en` for missing keys).
- `docs/firmware/manifest.json`: current auto-flash release metadata.
- `docs/firmware/firmware.bin`: Pages-served copy of the latest C3 release bin.
- `docs/firmware/firmware-x4pro.bin`: Pages-served copy of the latest X4 Pro
  release bin (absent until a release ships the asset).
- `docs/index.html`: site entry point.
- `scripts/sync_autoflash_firmware.py`: pulls latest release metadata and bins.
- `.github/workflows/sync_autoflash_firmware.yml`: manual sync (its `branch` input names the branch GitHub Pages deploys from, default `master`); stages
  `docs/firmware` as a directory so new or removed copies are committed.

## Manifest Schema

The top level keeps the historic flat fields for the C3 image so older page
copies and tooling keep working, and adds a `devices` object:

```json
{
  "name": "CPR-vCodex",
  "version": "<tag>",
  "firmwareUrl": "firmware/firmware.bin",
  "downloadUrl": "https://github.com/<repo>/releases/download/<tag>/<tag>.bin",
  "size": 6141856,
  "sha256": "<hex>",
  "source": {"type": "github-release", "repo": "<repo>", "tag": "<tag>", "asset": "<tag>.bin", "publishedAt": "...", "assetUpdatedAt": "..."},
  "devices": {
    "x4":    {"board": "x4",    "chipFamily": "ESP32-C3", "environment": "gh_release",       "path": "firmware/firmware.bin",       "asset": "<tag>.bin",       "downloadUrl": "...", "size": 0, "sha256": "...", "appSlotSize": 6553600, "assetUpdatedAt": "..."},
    "x3":    {"board": "x4",    "chipFamily": "ESP32-C3", "environment": "gh_release",       "path": "firmware/firmware.bin",       "asset": "<tag>.bin",       "downloadUrl": "...", "size": 0, "sha256": "...", "appSlotSize": 7798784, "assetUpdatedAt": "..."},
    "x4pro": {"board": "x4pro", "chipFamily": "ESP32-S3", "environment": "x4pro-gh_release", "path": "firmware/firmware-x4pro.bin", "asset": "<tag>-x4pro.bin", "downloadUrl": "...", "size": 0, "sha256": "...", "appSlotSize": 8257536, "assetUpdatedAt": "..."}
  },
  "new_install_prompt_erase": false,
  "builds": [
    {"chipFamily": "ESP32-C3", "board": "x4",    "parts": [{"path": "firmware.bin",       "offset": 65536}]},
    {"chipFamily": "ESP32-S3", "board": "x4pro", "parts": [{"path": "firmware-x4pro.bin", "offset": 65536}]}
  ]
}
```

Rules:

- `devices.x4` and `devices.x3` are mandatory and must match
  `firmware.bin`; `devices.x4pro` and the ESP32-S3 `builds` entry appear only
  when the release has the X4 Pro asset.
- The page resolves the image by the selected device's `firmwareKey`; C3
  devices fall back to the flat fields when `devices` is absent, the X4 Pro
  never falls back.
- `pre_release_check.py` verifies every present device entry against the
  local file (size, SHA-256, path, chip family, slot size, download URL tag)
  and fails if `firmware-x4pro.bin` exists without a `devices.x4pro` entry.

## Release Sync

Use:

```bash
python scripts/sync_autoflash_firmware.py --repo franssjz/cpr-vcodex
```

The sync downloads `<tag>.bin` (required) and `<tag>-x4pro.bin` (optional),
applies per-image size gates (C3 <= 6,553,600; X4 Pro <= 8,257,536; both
>= 1,000,000), writes the local copies, regenerates the manifest and the
`FALLBACK_RELEASE` block in `flash.html`, and rewrites the tag and download
URLs in `README.md`, `docs/assets/site.js`, `docs/index.html`, and
`docs/flash.html`. URL rewrites are suffix-aware: `<old>-x4pro.bin` links
become the new X4 Pro URL, plain `<old>.bin` links the new C3 URL. If the new
release lacks the X4 Pro asset, a stale `firmware-x4pro.bin` is removed.

After sync, validate:

```bash
python scripts/pre_release_check.py --tag 1.5.0.25-cpr-vcodex --skip-build --allow-existing-tag
```

## Flasher Flow

1. Choose device (`x4`, `x3`, `x4pro`); the choice is remembered locally.
2. Request a serial port (Espressif VID 0x303a; PID 0x1001 for the C3
   devices, any Espressif PID for the X4 Pro).
3. `espLoader.main()`, then compare `espLoader.chip.CHIP_NAME` (esptool-js
   0.5.7: `"ESP32-C3"` / `"ESP32-S3"`) with the selected device's `chip`.
   On mismatch, abort before any flash read or write.
4. Read and validate the partition table against the device's expected table.
5. Fetch the device's image, check max/min size, exact manifest size, and
   SHA-256.
6. Read `otadata`, write the inactive OTA app slot, write `otadata` with state
   NEW for the new slot.
7. Reset. The C3 reset uses the manual RTS/DTR sequence (esptool-js's
   USB-JTAG reset is a no-op on native USB). The ESP32-S3 cannot be reset over
   USB serial at all, so the X4 Pro shows a note: unplug and replug USB, then
   hold Power until it boots.

## GitHub Pages

Pages is intended to publish from `master` and `/docs`. Do not reintroduce a
`gh-pages` branch unless there is a strong reason and the release process is
updated accordingly.

Live URL:

```text
https://franssjz.github.io/cpr-vcodex/
```

If the public page shows an old version, check:

- repository Pages source settings;
- latest commit on `master`;
- `docs/firmware/manifest.json`;
- browser or CDN cache;
- the Pages deployment workflow.

## Flasher Safety

- Validate firmware size against the selected device's OTA app partition.
- Validate SHA-256 against the manifest entry for that device.
- Refuse suspiciously small firmware.
- Refuse to continue when the connected chip does not match the device.
- Keep Web Serial errors user-readable.
- Do not weaken partition-table validation without hardware testing.
